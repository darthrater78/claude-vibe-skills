**Key files:**
- `skills/dev-skills/checks/enforce.py`:
  - `simple_commands()` has a `ps` flag: PowerShell lexing, no `\` escapes,
    no backtick subshells
  - `split_heredocs()`: a heredoc body counts as commands only when a shell
    reads it (`SHELL_READERS`), unquoted data bodies are scanned for `$( )`
  - `unwrap()`: `program_name()` normalizes `git.exe`/paths/case; unwraps
    `pwsh -c`/`-EncodedCommand`, `cmd /c`, `iex`, here-strings, and
    `start_process()` (its `-WorkingDirectory` becomes `git -C`, never a cd)
  - `file_edit_check()`: in semi-autonomous mode gate rows skip B5 only when
    the file is semi-autonomous before *and* after the edit
  - `WRITE_HINT`: PowerShell/cmd write cmdlets, aliases, `[IO.File]::`
- `skills/dev-skills/SKILL.md` `hooks:`: matcher includes `PowerShell`; Python
  tried as `python3`, `python`, `py -3` (unquoted `$py` on purpose)
- `scripts/test-checks.py`: `pwsh()` helper, `ENC` for `-EncodedCommand`

**Decisions made:**
- Heredocs fail closed where it matters: any shell token on the heredoc line
  (`bash <<EOF`, `cat <<EOF | sh`) keeps the body checked as commands
- The semi-autonomous B5 skip covers gate rows only; mode, decline,
  host-network and waiver lines always ask
- Start-Process `-WorkingDirectory` is modeled as `git -C` so it can't leak a
  directory change to later commands in the chain

**Open items:**
- Not tested on a real Windows machine: the `py -3` hook path and the
  PowerShell tool were exercised only through a shim and payloads on Linux
- Known gap (documented nowhere yet): git run by a script file or by an
  interpreter (`python3 -c "subprocess.run(['git','push'])"`) isn't seen.
  Worth a line in ENFORCEMENT.md "What they can't catch"
- Diagnostic runs should chain with `&&`: a `;` chain this session ran a
  `git pull` after a failed checkout (local fast-forward only, disclosed)

**Shell environment:** Linux bash (local, same clone); tag and ref-deletion
